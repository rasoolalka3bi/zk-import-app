# إضافة موظفين (ZKImportApp)

تطبيق أندرويد مصغّر مبني على تطبيق إدارة أجهزة البصمة، وظيفته واحدة: أن يستورد
شخص في الفرع ملف موظفين وبصماتهم إلى جهاز البصمة، بلا خبرة تقنية.

## ما الذي يفعله

شاشة واحدة بثلاث خطوات: عنوان الجهاز، ثم اختيار الملف، ثم زر الإرسال، ثم نتيجة
واضحة مع زر يرسلها إلى المسؤول عبر واتساب.

## قرارات مثبّتة في الكود (لا تظهر للمستخدم)

- **لا كتابة فوق الموظفين الموجودين** — يضيف الجدد فقط ولا يمسّ أحداً.
- **البصمات تُنقل دائماً.**
- **لا يوجد أمر إعادة تشغيل للجهاز** في هذا التطبيق أصلاً.

## ما ورثه من التطبيق الأصلي (مسار الاستيراد نفسه)

- الاتصال عبر TCP أولاً ثم UDP احتياطاً.
- قراءة قائمة الموظفين والتحقق من اكتمالها قبل أي كتابة.
- تعطيل الجهاز أثناء الكتابة وإعادة تفعيله بعدها.
- إعادة قراءة كل بصمة بعد كتابتها ومقارنتها بايتاً ببايت، مع إعادة محاولة واحدة.

## إعداد مفتاح التوقيع (مرة واحدة)

الملف `release.jks` وكلمة السر أُرسلا إليك مع المشروع. **احتفظ بهما**: بدونهما
لن تستطيع إصدار تحديث يُثبَّت فوق النسخة القديمة.

في المستودع على GitHub، افتح:
Settings ← Secrets and variables ← Actions ← New repository secret

وأضف أربعة أسرار:

| الاسم | القيمة |
|---|---|
| `KEYSTORE_BASE64` | محتوى الملف `release.jks.base64.txt` كاملاً |
| `KEYSTORE_PASSWORD` | كلمة السر المرسلة |
| `KEY_ALIAS` | `zkimport` |
| `KEY_PASSWORD` | نفس كلمة السر |

بعدها ينتج كل بناء نسخة **release موقّعة** جاهزة للإرسال. وإن لم تُضَف الأسرار،
يبني المشروع نسخة تجريبية بدلاً منها حتى لا يخرج بملف لا يُثبَّت.

## خطوات ترسلها مع التطبيق للمستلم

1. ثبّت الملف المرسل. إن ظهر تحذير «مصدر غير معروف»، اسمح بالتثبيت من التطبيق
   الذي فتحت منه الملف.
2. اتصل بشبكة الواي فاي التي عليها جهاز البصمة.
3. افتح التطبيق، واكتب عنوان الجهاز، واضغط **فحص الاتصال** حتى تظهر «متصل بالجهاز».
4. اضغط **اختيار الملف** واختر الملف المرسل إليك.
5. اضغط **إرسال الموظفين إلى الجهاز** وانتظر حتى تظهر النتيجة.
6. اضغط **إرسال النتيجة إلى المسؤول**، ثم اضغط زر الإرسال داخل واتساب.

## ملاحظات

- يعمل على أندرويد 7 فأحدث. لا يعمل على آيفون.
- الاتصال بالجهاز عبر الشبكة المحلية فقط، لا عبر الإنترنت.
- ملف الاستيراد يحتوي بصمات الموظفين، فهو بيانات حساسة.
